## 3. 已解决的障碍

以下是在 9 月 19-21 日两次团队交付中 **彻底解决** 的关键障碍：

### ✅ 障碍 1：EVO 进化循环断裂（原 P0-1）
**之前**：「record-only」修复模式 → `fix_catalog.json` 从未创建 → `evo_iter` 始终为 0  
**之后**：`FixExecutor` 类实现（replace/insert/append/rollback）+ `--auto-fix` 自动执行 → 18 个测试用例验证

### ✅ 障碍 2：Mario 卡死 162s+（原 P0-2 + P1-1）
**之前**：circle_loop/micro_loop_weave 反复出现 → stuck_duration 持续积压 → 3 条 pattern 因 telemetry 缺陷完全失效  
**之后**：ground_angle gate 修复 + breakout_gain=0.35 部署 + 5 字段 telemetry 补全 → 23 个 stuck 测试通过

### ✅ 障碍 3：Fallen recovery 修复延迟（原 P1-2）
**之前**：R31-fix7/fix9 已部署但未验证  
**之后**：自适应 burst 公式验证（7个单元测试）+ Coach 多巴胺偏置验证（4个端到端测试）= 17 个测试全过

### ✅ 障碍 4：视觉覆盖度 ~38% 停滞（原 P1-3）
**之前**：EMD 运动检测停留在设计讨论 → 从 S3 → S8 多轮分析无落地  
**之后**：4 方向 EMD (Hassenstein-Reichardt 相关器) 实现 → ON/OFF 双通路 → 10 个 flow_json 字段暴露 → 18 个测试 → 覆盖度从 ~38% 提升至 ~50%

### ✅ 障碍 5：CX 导航回路不完整（原 P2-2）
**之前**：CX-1 罗盘自主化已完成 → CX-2 锚点积分 + CX-3 目标竞争未实现  
**之后**：AnchorPathIntegrator + MultiSourceGoalCompetition 实现 → 38 个测试 → 111 回归测试通过

### ✅ 障碍 6：单 SM64 场景瓶颈（原 P3-2）
**之前**：只有 SM64 Mario 一个验证场景 → 脑模型能力迁移性无法验证  
**之后**：FlyGym 果蝇身体仿真环境 → 42 关节六足 CPG 步态 → 脑模型集成验证 → 24 个测试

### ✅ 障碍 7：版本混沌（原 P2-1）
**之前**：4 处版本声明不同（2.23.6/2.23.7/2.23.10/2.23.11）  
**之后**：全部统一为 2.23.11 → 一致性自检

### ✅ 障碍 8：文档过时（原 P3-1）
**之前**：docs/analysis/ 下大量过期文档无状态标记  
**之后**：16 个文件标记为已废弃、8 个标记为已实现、更新 README 索引

### ✅ 障碍 9：EVO 健康度无法度量（原 P2-3）
**之前**：`evolution_health_trend.jsonl` 仅 1 行  
**之后**：HealthTrendCollector 常驻采集 + /health-trend.json 端点 + 仪表板面板 → 12 个测试

### ✅ 障碍 10：治理性基础设施缺口（治理修复 5 项）
**之前**：WSL 反复掉线、窗口不显示、Phase 6 低效、无契约审计、无门禁  
**之后**：tmux 6 层防护启动器 + SM64 窗口正确显示 + 贝叶斯进化优化 + CI 门禁 + 23 项启动回归 + soak 监控

## 4. 当前仍面临的主要挑战

经过两轮团队交付后，以下 **新一轮** 挑战浮出水面：

### 🔴 挑战 A：视觉覆盖度仍有 50% 差距
- **当前**：从 ~38% 提升至 ~50%（EMD 4方向已实现）
- **剩余**：颜色/UV 视觉通道、小目标追踪、多巴胺调制学习、髓质级信息压缩率 1/50,000
- **瓶颈**：这些能力涉及更深入的神经解剖建模，实现复杂度递增

### 🔴 挑战 B：第二场景的端到端集成验证未完成
- **当前**：FlyGym 环境已搭建、CPG 步态已实现、脑模型合成帧已验证
- **剩余**：
  - FlyGym 与 SM64 脑模型实例的实时切换机制
  - 实际运行 FlyGym 仿真需要大量的视觉预处理（raw_vision → EMD 实际输入）
  - **风险评估**：FlyGym v1.2.1 的 `Simulation` 接口是否完全兼容 Fly64 的 1536 点视网膜采样

### 🔴 挑战 C：EVO auto-fix 尚未常驻运行
- **当前**：FixExecutor 已实现并通过测试
- **剩余**：
  - `--auto-fix --interval 30 --max-iterations 0` 常驻模式未实际启动验证
  - 实际运行中 fix_template 的编辑能否正确匹配代码变化（行号漂移问题）
  - 多轮修复后的回滚安全性

### 🔴 挑战 D：测试框架膨胀（85 个测试文件）
- **当前**：~85 个 Python 测试文件，涵盖 1,000+ 测试用例
- **风险**：
  - 测试运行时间可能从秒级增长到分级
  - 部分测试可能存在重叠覆盖
  - 测试间可能存在隐式依赖（共享状态）

### 🔴 挑战 E：跨领域论证仍然缺乏实证
- **当前**：理论分析充分（6 领域适配架构图）
- **剩余**：FlyGym 场景仅验证了果蝇身体仿真环境中的运动控制，尚未验证金融/保险领域场景

### 🔴 挑战 F：仪表板功能缺口
- **当前**：基础布局完成、神经活动可视化方案已设计、EVO 健康趋势已添加
- **剩余**：S8 提出的全链路 UI 展示方案尚未完全落地
