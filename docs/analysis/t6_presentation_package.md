### Slide 4 — 通用迁移框架

**标题**: 六步迁移法 — 从任意源域到任意目标域的标准化流程

**核心信息**: 无论目标领域如何，六步迁移框架保持恒定

```
S1: 输入适配 → S2: 奖励重写 → S3: 动作映射 → S4: 环境对接 → S5: 监控适配 → S6: 闭环验证
```

| 步骤 | 工作量 | 核心操作 | 影响层 |
|------|-------|---------|-------|
| S1 输入适配 | 中-高 | 替换传感器管道为目标域特征 | L1 |
| S2 奖励重写 | 中 | 2-5个奖励信号重定义 | L3 |
| S3 动作映射 | 低-中 | 4自由度扩展为目标域动作基元 | L0→输出 |
| S4 环境对接 | 低 | mmap桥接扩展为目标控制协议 | 🔌 |
| S5 监控适配 | 低 | 仪表板指标重命名 | 🔌 |
| S6 闭环验证 | 低 | 诊断指标替换 | L5 |

**5级决策仲裁链**: 反射 > LIF内生决策 > 多巴胺门控学习 > LLM咨询 > 局部降级

### 技术FAQ准备

**Q: Fly64和深度学习相比的优势？**
A: 确定性可复现(种子64)，可审计决策(因果链+70+指标)，低能耗(1mW vs GPU数百瓦)，事件驱动天然适配不规则数据。参考Slide 2-3。

**Q: 50Hz实时性够用吗？**
A: 对工业质检(>100件/分钟需GPU加速)、机器人导航(50Hz足够)够用。自动驾驶需GPU加速到200Hz+（详见Slide 18风险部分）。

**Q: 如何保证跨领域泛化？**
A: L0推理引擎输入/输出无关，改变的是L1-L3层的编码器/奖励/动作映射。六步迁移法保证流程化（Slide 4）。

**Q: 有实际部署案例吗？**
A: StonkFly量化交易(2021起运行)，FlyMuse Steam游戏(2026上线)，SM64/Doom/HL/MC多游戏验证。
