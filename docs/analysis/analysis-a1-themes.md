# A1 · Fly64 主题主线分析：项目在解决什么问题

> **任务**：t1 [A1] 主题主线分析 · **产出**：本文件
> **数据源**：`export logs/` 全部 17 个 zip → `.tmp/sessions_v3/`（11 个唯一 session + 120 个 jsonl 分片，含 subagent）
> **交叉验证源**：`.tmp/sessions_v3_analysis.json`（v3 脚本产物）、`docs/analysis/session_logs_analysis_v3.md`
> **可复现脚本**：`scripts/analyze_themes_a1.py`（本报告全部数字由它生成，中间产物 `.tmp/a1_themes/{questions.json,quant.json,quant.md,quotes.md}`）
> **分析时间窗**：2026-09-10 → 2026-09-22（北京时间 UTC+8）
> **一句话结论**：项目在**用一只果蝇脑（MaleCNS 166,700 LIF 神经元）驱动 SM64 马里奥**；11 天里 874 条人类提问真正在打的是三场仗——**(1) 让马里奥别转圈、真能动；(2) 让教练/EVO 的建议真能落到行为上；(3) 让这条"脑模型↔SM64 桥接"的工程链路别塌**。第 (3) 场消耗了 55% 的提问量，是最大的隐性成本。

### 1.1 提取管线

| 步骤 | 规则 | 结果 |
|---|---|---|
| 唯一 session 识别 | 目录名前 8 位 hex 归并；重复导出取**提问数最大**者 | 11 个唯一 session（17 个导出目录） |

| 真人提问 | `data.source.kind == "user"` **且** 非 AgentTeams 协议文本 | **874 条** |
| 协议噪声剔除 | ①`AgentTeams automatic task assignment…` ②`You have joined the team … as a member…` | 89 条 |
| 系统注入 | `source.kind ∈ {plugin, subagent-settled, agent-message, skill-catalog, agent-teams-command, goal}` | 1362 条 |

| `agent-teams-command` | 44 | `/agent-teams` 斜杠命令展开 |
| `goal` | 2 | 目标轮次 |

> **方法论修正**：v3 脚本（以及本脚本第一版）用 `data.get("rpcId")` 判断"来自 Web 客户端"，但该字段实际位于 `data.source.rpcId`，`data.rpcId` 恒为 `None`。所以两者的真人过滤器实际退化为"`source.kind == "user"`"，这也是 81 条入队通知被误计为真人提问的根因。修正后：874 条中 **825 条带 `source.rpcId`**（Web UI 直输）、**49 条无 rpcId**（`/agent-teams` 命令轮与子代理任务书，仍是人类撰写）。

### 4.1 三阶段分布

## 9. 局限与不确定度

1. **关键词聚类有主观性**：15 条主线的边界由我定义，长文本（尤其粘贴回流的长报告）会同时命中多主线。缓解措施：同时给出 primary / coverage 两种口径 + 与 v3 独立词表对账（§7），结论在 13/14 主题上一致。
2. **19.5% 未命中**：170 条（其中 148 条 ≤12 字）不归属任何主线，已显式列出而非隐藏；它们多是短指令与凭据串，不改变主线排序。
3. **"提问"不等于"问题"**：人把代理的报告贴回来（48 条）会让某些主题的热度被高估；本报告用类型标注加以区分，但无法完全消除。
4. **idx 编号口径**：本报告 `session:idx` 与 v3 的编号不同（v3 未剔除协议噪声），引用时需以本报告为准。
5. **子会话并入父会话**：subagent 的会话记录被计入其父 session（与 v3 一致），因此"某 session 的工具调用/注入数"包含其子代理活动；但**人类提问**只可能出现在父会话（子代理无人类输入），对 §2 的主线量化无影响。
6. **主题归属≠工作量**：提问次数只反映"人问了多少次"，不反映代理实际做了多少工作（如某个 1 条提问背后可能有 200 次工具调用）。

## 10. 结论：项目在解决什么问题

**一句话**：把一个纯生物机理的果蝇中枢神经系统（166,700 LIF 神经元 / 25.6M 突触）接到实时游戏环境里，让它**自主驾驶**马里奥 —— 项目所有对话最终都服务于这一个目标。

**五条主线（按人类注意力排序）**：

1. **E2 运行环境与桥接（238 条 / 27.2%）**：让脑模型、SM64、WSL 显示、8765 服务这几块同时活着。这是**成本最高、最反复、最不"性感"**的一条线，也是"看不到进展"的根源。
2. **P7 脑模型与神经机制（184 条 / 21.1%）**：反复确认"这个行为是不是真的由神经元/多巴胺/蘑菇体决定"，而不是被一层 if-else 逻辑伪造的。人的核心怀疑是 `38542b1c:36` 那句"**不要使用逻辑判断**"。
3. **P1 运动质量（175 条 / 20.0%）**：从 09-11 的"为什么总是转小圈"到 09-22 的"大部分动作没有尝试（oscillating 反射把控制钳死）"，**同一个症状形态伴随了整整 11 天**。
4. **E1 可观测性（166 条 / 19.0%）**：因为无法直接看神经系统，人必须靠 dashboard/trajectory/health 这些界面"看见"状态；界面一坏，整条研发循环就断。
5. **P3 Coach 教官闭环（163 条 / 18.6%）**：LLM 教官给了建议 → 但建议到不了行为。这条线在中期（09-14→09-17）占据 118 条，是项目**最密集的一次攻坚**。

**主题演变三句话**：**09-10~09-13 搭台**（跑起来、看得见）→ **09-14~09-17 攻坚**（Coach 建议生效、EVO 修复落地、动作别单调）→ **09-18~09-22 收敛验证**（提问量降 88%，主题变成"重启/换显示模式/验参数是不是真生效"）。

**当前的真正困境（本报告视角）**：不是想法不够，而是**"机制齐全但生效性未验证"**——晚期的提问几乎全是"检查是否生效 / 修复后是否还转圈 / 这个键名到底有没有传下去"。这与 A2/A3 的下游任务应当直接对齐：**先建立"变更→可观测行为"的生效性验证闭环，再谈新能力。**
