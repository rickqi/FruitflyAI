## P0 级 — 立即（0–5 天）

### P0-1 信用分配通路审计（最高优先）

**为什么**：并行审计 M1 判定"决定行为的变量与所有自适应面不重叠"，我在 P0-4 实机验证中独立复现了其中一例（教练参数被钳位吃掉）。但**完整的断路清单尚未建立**。

**做法**
1. 静态提取"决定行为的变量"全集：从 `main.py` 中取所有被写入 `model.*` / `memory_ctrl.*` / `control.*` 的字段（可用 AST）。
2. 对每个变量，反查**写入者**来源：默认值 / 注册表参数 / 教练 strategy / EVO `_inject` / 硬编码。
3. 产出 **变量 × 自适应面 矩阵**，标出：
   - 有自适应写入者 ✅
   - 只被硬编码写入 ❌（断路）
   - 被写入但下游被钳位/覆盖 ❌（半通）

**验收**
- 矩阵覆盖所有行为相关变量，无遗漏（与 `brain_tunable_params.json` 的 39 参数交叉校验）
- 每个 ❌ 项附 `file:line` 与可复现验证命令
- 产出 `docs/analysis/analysis-credit-assignment-matrix.md`

**预估**: 1 天

### P0-2 让 EVO 产出可执行 fix

**为什么**：审计实测 **19 条 fix 中 16 条可执行行数 = 0**（合计 7 行代码 vs 87 行注释）；且 `ramp_trap` 的条件键 `position_unchanged_30s` **全仓无生产者**，pattern 结构上永不可达。

**做法**
1. **fix 可执行性**：让 fix 生成路径只产出结构化指令（`# File/# Find/# Replace` 等），拒绝纯注释占位；对无法结构化的 finding 明确标记为 `advisory`（而非伪造成 fix）。
2. **pattern 生产者校验**：加载 `default_patterns.json` 时，校验每个条件键在遥测中**有生产者**；无生产者即报错（不静默）。
3. 为上述两点各加回归测试。

**验收**
- 新生成的 fix：`可执行行数 > 0`（断言）
- `position_unchanged_30s` 类无生产者键：加载期报错并列出键名
- `python -m pytest fly64/tests/test_fix_template_interpreter.py fly64/tests/test_pattern_catalog_health.py -q` → 0 failed

**预估**: 1–2 天

### P0-3 重启并守护进化闭环 + 停摆告警

**为什么**：审计实测闭环**最后写入 09-17 10:22:55，已停摆 7 天**；无进程、无锁、无计划任务。故障发生时闭环根本不在运行。

**做法**
1. 按项目契约（`setsid nohup` / tmux 守护）重启常驻 EVO 循环。
2. **加停摆检测**：若 `evolution_log.jsonl` 超过阈值（如 30 min）无新行 → 写告警（dashboard 端点 + 日志）。
3. 把"闭环存活"纳入环境契约自检（与 SM64/桥接同列）。

**验收**
- 闭环在线：`evolution_log.jsonl` 持续增长
- 人为 kill 循环 → 阈值内出现告警（提供 red→green 证据）
- `python fly64/scripts/verify_launch_contract.sh`（或等价）输出含"EVO 闭环"一项

**预估**: 1 天

---

### P0-4 修复 `has_fix()` 的一次性语义

**为什么**：`has_fix()` = "存在未回滚的 fix" ⇒ **一旦某 pattern 有了一条无效 fix，它永远不再生成新 fix**。审计漏斗显示 `11 fixes → 0 effective`，之后闭环只会重复记录 finding。

**做法**
1. 改为"近期有效 fix 存在才跳过"，或引入冷却期 + 允许在参数/代码变化后重试。
2. 补测试：一个 fix 被判无效后，**允许**该 pattern 生成新 fix。

**验收**
- 单测覆盖"无效 fix → 可再次生成"
- 不引入重复 fix 风暴（连续 N 轮内不无限生成）

**预估**: 0.5–1 天

## 判断本轮是否成功的四个问题

1. **通路是否打通？** → P0-1 矩阵中 ❌ 项是否都有修复计划或明确"有意硬编码"的理由
2. **EVO 是否能产出可执行修复？** → 新 fix 的可执行行数 > 0
3. **闭环是否活着且可观测？** → 日志持续增长 + 停摆有告警
4. **"建议是否生效"能否随时看到？** → `/memory.json` 的 `coach_applied` + `clamped_keys` 在实机可用

**四项全绿再考虑新增自适应面。** 在此之前新增自适应面只会加深 M1（更多信号进不了行为）。
