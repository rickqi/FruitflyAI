## 4. 当前主要困境

> 截至 2026-09-22（Brain v2.23.12 / Skill v3.5.0），项目处于**"机制基本齐全，但端到端行为有效性仍未验证"**的状态。

### 🔴 困境 1：Coach 链路刚修好，尚未实测验证

**证据**：`879d983 fix(EVO-072): active_strategy键名归一化 + coach合并写入 — 修复EVO进化值从未生效`

- 这是**最新一次提交**（仅次于 README 更新）
- 说明"EVO/Coach 写入的值从未真正生效"这个缺陷**刚刚被定位并修复**
- 但**修复后的实测效果尚未验证**——用户最近的抱怨"coach 建议未生效，未脱困"正是修复前的状态
- **风险**：六段链路中 ①②③⑥ 是否也随之修复，尚未确认

### 🔴 困境 2：参数系统膨胀到 39 个，治理成本高

**证据**：
- `218c6c0` 36 参数 / 5 段；`ea509a9` 又补 3 个 memory 参数 → **39 参数 / 6 段**
- `ea509a9` 发现 **5 个参数是"死参数"**（注册在 escape.*/reflex.* 但实际从 _expl 镜像，面板 POST 根本到不了消费者）
- 连续三个 commit（`85f2036`/`37724b8`/`f3501e7`）都在"接线"参数

**本质**：参数越来越多，但"注册了 ≠ 生效了"的**契约断裂**反复发生。这是同一类缺陷（机制存在、报告成功、无法生效）的第二次系统性爆发。

### 🟡 困境 3：探索/运动的行为有效性仍未被证明

- 探索三重死锁刚修（`5c86272`），frontier radius 刚调（20→50）
- "动作单调、大部分动作没尝试"（S5:29）是**修复前**的最后一次观测
- 覆盖率、健康度长期偏低（S7:36 "分析 health 含义，偏低原因"）
- **缺少一个可信的"脱困成功率/覆盖率提升"量化基线**

### 🟡 困境 4：语义场景能力缺失（能力边界）

- "需要钥匙"这类文字提示无法识别 → 无法规划"取钥匙"（S8:13）
- 结论明确：属**超出果蝇脑能力**的部分，应由 LLM 教官层承担（S8:15,16,17）
- 但社交求助（SEEK-HELP）机制是否端到端可用，未见验证记录

### 🟡 困境 5：运维层反复出现 SM64 显示/启动问题

- WSLg 窗口不可见、屏幕外、FROZEN（S5:5,20–26；S3:61；`d04264e` 修窗口位置）
- 双显示模式（wslg/xvfb）刚加（`e0edc29`）
- **每次环境变动都会重新触发**，缺少稳定的启动契约自动校验

### 🟢 困境 6：测试套件规模已大，但基线噪声未清

- 89 个测试文件（README 称 600+ 用例）
- EVO-068 明确记录："Windows 套件长期带约 **40 个未分类失败**，真实回归会被淹没"
- 缺少"哪些失败是已知噪声"的显式基线清单
