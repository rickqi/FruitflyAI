## 3. 跨会话横切瓶颈

从 7 个会话和 79 条演化记录中归纳出 5 项反复出现的瓶颈模式：

### 瓶颈 1：stuck_ramp 振荡

**表现**：马里奥在斜坡/地形过渡处反复 stuck→escape→stuck→escape 振荡，持续数分钟。
**出现会话**：9e9d4023, 38542b1c, 047eec9d
**修复轮次**：EVO R6（自适应冷却）、R10（局部突围）、R13（进度门控+镜像交替）、R15（悬崖对峙）、R16（震荡突破电流）、R17（breakout_hint）、P1 进化轮
**当前状态**：已大幅缓解（多个机制协同），但极端地形下仍有残余
**根因**：反射冷却缩短→micro_loop 重触发→转向无前进→stuck 不复位→自增强反射风暴

### 瓶颈 2：视觉场景识别 → 行为差距

**表现**：识别系统正确标记场景（熔岩/悬崖/室内），但识别结果无法驱动行为改变。
**出现会话**：38542b1c
**修复轮次**：EVO R9（围闭度→室内）、R15（cliff_tangent_bias）、R19（scene_danger→forward 抑制）
**当前状态**：EVO R19 实现了识别→行为闭环的雏形（scene_danger→forward 抑制），仍为非学习型硬编码
**关键差距**：识别结果未进入蘑菇体学习管道，无法通过经验优化

### 瓶颈 3：教练通路的断续生效

**表现**：LLM Coach Advice 说了就算但实际不生效（死键码、未接线、参数不消费）。
**出现会话**：047eec9d, 38542b1c
**修复轮次**：t13（4 项根因：死键接线、触发链、prompt 语义卡、HTTP 400）、R31-fix8（turn_and_go 死键码）、R31-fix9（教练→多巴胺通路）
**当前状态**：多个断点已修复，但整体仍脆弱——prompt 工程、接线一致性、环境变量传递均可能引入新断点
**根因**：跨模块契约缺乏自动化验证（写端与读端无共享 schema）

### 瓶颈 4：监控面板布局持续退化

**表现**：每次新增功能→CSS/layout 布局覆盖→section 选择器失效→新内容溢出/重叠。
**出现会话**：a909a5cd, 38542b1c, 047eec9d
**修复轮次**：多次 CSS 迭代（661b939→a30dfbb→cd555f8→d9bd246）、t16（P0-P2 可见性与布局系统化修复）
**当前状态**：已通过 ody.causal-off kill-switch 和 section.xxx-section 类选择器改善，但单页 dashboard 随功能增加仍是持续维护负担
**建议**：考虑前端模块化（非单页）或 CSS 契约测试

### 瓶颈 5：WSL↔Windows 双向同步 + 桥接可靠性

**表现**：共享内存桥在宿主 kill/重启后静默失效；rsync --delete 误删 plugin 目录；CRLF 行尾导致 WSL bash 失败。
**出现会话**：99cab60f, 38542b1c, 047eec9d
**修复轮次**：t18（启动契约固化）、t19（seqlock 停更看门狗）、清理轮（--delete 禁用、CRLF→LF）
**当前状态**：检测已就绪（stale 徽章），auto-restart 为已知待办但未实现
**根本矛盾**：Windows 是源码权威，WSL 是部署目标，两套环境差异持续产生摩擦
